## 0. 给执行 Agent 的说明

- 先读 README.md、01-tokens.md、02-components.md,再读本文。颜色只用 token 名称(见 01 §2),组件只引用 C16–C21 等编号，规格以 02 为准，本文只写页面特有的差异。
- **不重写既有 Function 与功能。** 只改 UI 层(Composable 的版式与样式)。ViewModel、数据层、设置语义、导航逻辑不改，除非该项列在 05-approved-changes.md。撰写时标出的【待确认】已由维护者答复(§6、05 §8);实现时如果又遇到 05 没有列出的新数据或新逻辑:**先停下来问维护者，不要自行实现**。
- **平台闸门**:本文的版式以新增的 Apple 版 Composable 实现，由 `isApple()` 选择;macOS 专属的窗口、`MenuBar`、快捷键用 `isMacOS()`。Windows / Linux 走既有画面(05 §8.1)。
- **快捷键**:只做 05 C2 列出的快捷键(⌘K、⌘,、⌘R、⌘I、⌘T、⌘← / ⌘→、↩)。⇧⌘R、⌘⌫、资料源编辑器的 ⌘R、按住 ⌘ 点选多选都**未批准**,菜单与提示文字里也不要出现。多选只走「選擇」模式(05 D2)。
- **文案**:设计稿新出现的提示与按钮文字一律新增字串 key(05 §8.3)。
- 标「见 05」的项目已获维护者批准，实现细节、涉及文件和验收以 05 为准。
- 表格类页面的对齐是验收重点:**表头和每一行共用同一组列宽**(同一个 `Row` 宽度规则，或同一组 `weight`/固定宽度常量),数字列的对齐方向照本文表格。不要让表头和内容各自排版。
- 设计稿里的番名、人数、版本号、日期、网址都是示意数据，以运行时数据为准。

### 1.3 侧边栏高亮规则

- 一级页面高亮自己的入口。
- 从某页推入的详情页，沿用**来源入口**的高亮，即推入前所在的一级入口;不要按页面类型写死。例如从探索打开条目详情，高亮「探索」;从快取打开单番下载详情，高亮「快取」。
- 搜索结果页:侧边栏不高亮任何入口，搜索框显示 accent 描边并填入查询词。
- 通知中心:侧边栏不高亮入口，底部铃铛显示选中状态(tint 底 + accent 图标)。
- 播放页:不显示主侧边栏(见 §3.8)。
